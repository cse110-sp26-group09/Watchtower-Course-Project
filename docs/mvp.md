# WatchTower MVP

## Feature List (Refined from Initial Brainstorm)

### Must Have (MVP)

These features are required for Sprint 1 demo:

1. Add a small JavaScript tracking script to a demo website  
2. Capture frontend JavaScript errors  
3. Capture basic performance metrics  
4. Capture simple user feedback or rating signals  
5. Store captured events in a simple structured format  
6. View the events in a dashboard  
7. Filter or separate events by type  
8. Connect events/errors to a mock deployment or build version  
9. Use a deployed website that explains and demonstrates the project  

---

### Nice to Have (If Time Allows)

These improve usability but are NOT required:

10. View interaction count for UI elements on screen  
11. Basic visualization of event flow or relationships  
12. Notifications that can be disabled  

---

### Not in Sprint 1

These are explicitly OUT of MVP scope:

13. Feature flagging (simple on/off)  
14. A/B testing for site deployment  
15. Advanced analytics or complex dashboards  
16. Real backend infrastructure  
17. Authentication system  

---

## Feature Success Criteria

Each MVP feature must have a simple success condition:

- Error tracking → Errors triggered in demo appear in dashboard  
- Performance tracking → Load time is recorded and visible  
- Feedback → Submitted feedback appears in dashboard  
- Dashboard → User can view and distinguish event types  
- Deployment linking → Events show associated version label  

---

## MVP Definition

The MVP is successful if:

A developer can open the demo site, trigger an error, performance event, or feedback signal, and then see that event correctly displayed and categorized in the WatchTower dashboard.

---

## Sprint 1 Constraint

For Sprint 1, focus is on:

- Defining MVP clearly  
- Research and alignment  
- Prototype direction (not full implementation)
